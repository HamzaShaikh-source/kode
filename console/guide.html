How to use K.O.D.E.

The Brain is a small server you run. Teammates run a tiny agent that connects outward to it. You open the console in a browser.

Start the Brain

From the backend folder, with the hub enabled:

python -m uvicorn app:app --port 8000

Open http://localhost:8000/console. On the Brain's own computer no key is needed. From another computer the console asks for the lead key, which is stored in backend/.hub_key. To let other machines connect over your network, bind the server to your LAN address and use that address in the invite.

At a hackathon

One person (the lead) runs the Brain. Everyone else only needs Python, git, the GitHub CLI and their own coding agent.

  1. Same Wi-Fi: start the Brain with python run_kode.py --lan (allow it through the firewall when Windows asks). Teammates use your PC's address, for example http://192.168.1.20:8000.
  2. Different networks: start a tunnel in front of port 8000, for example cloudflared tunnel --url http://localhost:8000, and start the Brain with python run_kode.py --public-url https://your-name.trycloudflare.com, or paste that address on the Settings page.
  3. Invite each teammate from Team. Each one opens the link on their laptop and runs the single command it shows.
  4. Create a project, pick a planner, choose Turbo permissions, approve the plan, and watch it build.

The console asks for the lead key whenever it is opened from anywhere but the Brain's own PC, including through a tunnel. Invite links work once and expire (10 minutes to 24 hours, your choice).

Invite a teammate

  1. Open Team and press Invite teammate.
  2. Type their name, choose how long the link works and your access (Full access is the default for the lead), and check the address teammates use to reach this Brain.
  3. Press Create invite link and send them the link. It works once.

When their machine connects, the Team page lists it with what it is ready for: git installed, GitHub CLI logged in, and the identity its commits will use.

Join as a teammate

Open the link from your lead on your own laptop. On Windows the page has a Download installer button (a plain-text kode-join.ps1 you can read first) and one command to run it in PowerShell; Windows Defender blocks the usual one-line download-and-run trick, so we do not use it. On macOS and Linux it is a single curl | sh command. It downloads a small agent from your lead's Brain into kode-node in your home folder, sets up a private Python environment, checks git, the GitHub CLI and your coding agents, and connects. You can read the script first with the button next to it.

Next time, run start.ps1 (Windows) or ~/kode-node/start.sh. Your member console link, with the kill switch, is printed when the agent connects. Projects are cloned into kode-workspace in your home folder, and commits use your own git identity and GitHub login.

Run a project

This is the main workflow. You need every teammate's laptop connected, with git and the GitHub CLI (gh auth login) set up, and an agent installed on each (Claude Code, Antigravity, OpenCode, Codex...).

  1. Open Projects, press New project, write the brief, pick each teammate's agent, choose the Planner (Claude Code or Codex using that laptop's own login, one of your API profiles, or the Brain default if one is configured), and press Plan the project. Nothing is chosen for you silently.
  2. Review the plan: tasks, owners, the files each task may touch, the frozen contract and the verification command. Re-assign a task or ask for a re-plan.
  3. Choose agent permissions: Turbo (agents never ask; fastest), Supervised (a supervisor model answers their questions) or Ask me. Then press Approve and start building. The coordinator laptop creates a private repository (or uses yours) and pushes the contract and team rules.
  4. Each laptop clones the repository, creates a branch per task and starts its agent with the task file. The Projects page shows every task, its commits and a link to the live console.
  5. Finished branches are checked by code: edits outside the task's files and any contract edit are reverted, then a pull request is opened from that laptop and merged.
  6. When every task is merged, the verification command runs. If it fails, the model proposes fix tasks for the owners of the failing areas, up to three rounds.

Commits come from each laptop's own git identity, merges keep individual commits (no squash), and the Contributions panel is computed from git history (contribution means a meaningful share of the work, not an equal number of commits). Pick a repository name and Private or Public when you create the project; K.O.D.E. invites every teammate to the repository with write access and accepts the invitation on their laptop, then checks that each one can push. Add context (the event page, rules, PDFs, screenshots) and tick Let the planner ask me questions if you want it to check what you need before it plans. Choose each laptop's main agent and the extras or backups it may use; if an agent hits a limit, the next one takes over on the same branch. When verify, polish and judge are done you get a report to approve or send back with changes, and Hackathon complete remembers the team and agents for next time. Tick Hackathon mode to paste a problem statement instead of a brief: the agents research it, propose ideas, critique each other and vote, and the winning idea is built. Each teammate's agent session is reused for all of their tasks (at most a handful of sessions, not one per task), and the lead's own PC joins the team automatically so the lead gets real tasks and commits too. After the quality review an independent code judge scores the result like a hackathon panel and writes docs/SUBMISSION.md. Before a project is marked done, a quality review checks the README, tests, stray files, secrets and leftover TODOs, and an AI reviewer compares the result with your brief; anything it finds becomes a polish task. When an agent stops on a question (permission, file edit, trust folder), a supervisor model (the same one you chose as Planner) reads the screen and decides which keys to press. It never answers terms, logins, data-sharing or destructive prompts; those appear as cards for you, and fixed rules take over if the supervisor model is unavailable.

Honest limits: quality depends on the agents and models your team uses; the plan is only as good as the brief; a laptop that goes offline pauses its tasks until it returns.

Watch and control

The Brain page shows a live console for every session. Click one to open the full terminal with its plan, changed files and usage.

ModeWhat you can do
WatchRead only. The default.
SuggestPlace text in their prompt for them to send.
Co-pilotBoth of you can type. Expires automatically.
TakeoverOnly you type. Ends after 10 minutes at most.

Sessions that are waiting on a person show a Needs you chip and add to the count in the tab title.

Custom endpoints

On Models, press New profile: name, base URL, protocol, key, model list, and optionally prices and the context window. Use Test connection to check it.

When you start a session, pick the profile under Model source. Claude Code needs an Anthropic Messages endpoint, Codex needs the OpenAI Responses API, and OpenCode accepts OpenAI Chat or Responses. Hermes, Antigravity and shells cannot be redirected per session, and the dialog says why.

Orchestrator

Describe a goal, for example: "Find out who is blocked and ask them for a status line." It reads the team, reads screens, and proposes actions. In Ask autonomy every write shows an approval card. It can only type where the owner has granted co-pilot or takeover, and each run is capped at 12 steps, 15 minutes and 150k tokens. The model it uses is chosen on the same page.

Usage and context

Token counts and the context gauge are read from Claude Code and Codex transcripts. Other tools show unknown. Cost is an estimate: tokens times the per-million prices you set on a profile.

Safety model

  • Machines connect outward only. No inbound ports on teammates' laptops.
  • Control is enforced by the Brain and again by each teammate's agent.
  • Keys are encrypted at rest, injected into one session, and redacted from its output.
  • Pairing, starts, grants and the lead's input are written to an audit log.

When Wi-Fi drops, laptops restart, or the Brain restarts

A project is built to ride out the failures that happen at hackathons. Nothing needs a click unless this page says so.

What happensWhat K.O.D.E. does
A teammate's Wi-Fi drops for a momentTheir agent keeps working locally and reconnects by itself. The same terminal session continues; the task is not restarted. The task card shows "waiting" until they are back.
A laptop stays offline for a whileIts tasks wait and retry with a growing delay for up to 20 minutes, then ask you. If the laptop that merges and verifies goes offline, another online teammate takes that role.
A teammate closes the window or rebootsThey run start.ps1 (or ~/kode-node/start.sh) again. Their task restarts on the same branch with the work already committed, and Claude Code and Antigravity pick their previous conversation back up.
The agent crashesThe start script restarts it after 5 seconds. Starting it twice leaves one running: the newer one wins.
The lead restarts the BrainLaptops reconnect on their own, running projects resume automatically, and unfinished work is kept.
GitHub is unreachable or slowPushes, pull requests and merges retry automatically. A task is never stranded half-merged.
The Brain's address changes (new hotspot IP)Laptops remember the Brain's other addresses and try them. If none work, use a fresh invite link.
A machine was removed or the Brain was resetIts agent stops and says it needs a new invite link.

If you reload the console, or it loses the connection, it reconnects by itself, replays every terminal, and warns you instead of silently dropping what you type.

Troubleshooting

SymptomFix
Console asks for a keyOpen it on the Brain's computer, or paste the contents of backend/.hub_key.
Invite code rejectedCodes are single use and last 10 minutes. Create a new one.
Profile greyed out for a providerThe protocol does not match that agent. See the table on the Models page.
Context shows unknownThat tool does not expose it. Set a context window on the profile for custom endpoints.
A teammate installed or signed in to an agent after joiningNothing to redo: their agent re-checks every 15 seconds, so it appears on the Team page by itself. Press Rescan on their machine card to check right now. A "sign in needed" badge means it is installed but not signed in (run it once on that laptop).
"Auth failed" when joining againRun the new invite command again. A new invite always replaces an old saved login, and the old offline entry for the same person is replaced. If the invite itself is wrong or used, the agent falls back to its previous registration.
Locked out after wrong keysEight failures in five minutes pause attempts from that address. Wait and retry.
